# Алгоритм и параметры

## Поиск периода и фазы

`true_pixel.py` строит горизонтальный и вертикальный профили силы RGB-границ.
Единичные сюжетные края ограничиваются сверху, а повторяющиеся границы
усиливаются относительно них. Для каждого предполагаемого периода
независимо выбирается фаза каждой оси.

Размер псевдопикселя перебирается примерно с шагом 0.05 high-res пикселя.
Фаза проверяется примерно через 0.25 пикселя. Оценка учитывает энергию на
линиях регулярной сетки и фазовую когерентность. Последняя штрафует
период, который постепенно дрейфует относительно настоящих границ.

X и Y объединяются при близком размере ячейки. В реконструкцию входят
только полные ячейки; неполные поля по краям crop отбрасываются.

Автопоиск не привязан к левому верхнему углу. Для листа он вызывается
отдельно на каждом прозрачном high-res фрагменте.

## Alpha-aware цвет

От границ ячейки по умолчанию отступают на 18%. Это уменьшает влияние
генеративного размытия и межпиксельных кромок.

Для RGB берётся поканальная медиана. Для RGBA вычисляется видимая доля
ячейки; если она меньше 0.5, ячейка становится прозрачной. RGB считается
только по видимым образцам, а их веса равны alpha. Полностью прозрачные
RGB нормализуются в ноль при удалении ключа и реконструкции.

После сведения палитры скрытый RGB может иметь цвет палитры; на цвет
видимых пикселей он не влияет, поскольку его alpha равна нулю.

## Палитра

AAP64 автора Adigun A. Polack хранится в `true_pixel.py` и
`palettes/aap64.hex`. RGB переводится в линейный sRGB и OKLab; выбирается
ближайший из 64 цветов. Alpha сохраняется, дизеринг не применяется.

`palette: image` создаёт палитру конкретного изображения, а `none`
сохраняет восстановленные RGB. Для совместимых листов используется AAP64.

## Внутренняя обводка

Каждый видимый пиксель проверяется по восьми соседям. Если сосед прозрачен
или вышел за границу, RGB текущего пикселя заменяется на AAP64 `#242234`.
Alpha остаётся прежней, за пределами силуэта ничего не рисуется.
Доступно также четырёхсвязное соседство.

## Выравнивание и кадрирование

Прозрачные поля удаляются по alpha bbox. Изображение центрируется по X и
ставится на общую базовую линию. Холст добавляет только прозрачные поля;
масштаб и видимые пиксели не меняются.

Портретный crop работает в восстановленных пикселях. Сдвиг камеры вниз
означает увеличение Y начала crop. Все проверки границ выполняются до
сохранения результата.

## Модули

`pixel_ops.py` содержит общие операции; `pixel_stages.py` — их CLI.
Тонкие исполняемые файлы вызывают эти общие реализации, поэтому отдельный
запуск этапа и общий конвейер используют один и тот же алгоритм.
`pixel_pipeline.py` сохраняет промежуточные результаты и протокол решения
по каждой сетке.
